# Normalised STR Observation Model Specification

This document defines the STR observation model used for the Amarna pedigree
likelihood calculations supplied in this bundle.

The model evaluates

```text
P(observed STR call | true diploid genotype, observation-model parameters)
```

for each scored person-locus observation. Pedigree inheritance, founder priors,
and multiplication across loci are handled separately by the likelihood code.

## Input States

Each person-locus observation is encoded as:

```json
{"alleles": []}
{"alleles": ["a"]}
{"alleles": ["a", "b"]}
```

- zero alleles means no usable call is available;
- one allele means a partial single-allele call;
- two alleles means a complete unordered diploid call.

An empty allele list is treated as uninformative and contributes a constant
factor of 1.0. The likelihood is therefore conditional on the pattern of usable
reported calls.

## Allele Universe

For each locus, the callable allele universe contains every allele appearing in
the locus priors, explicit genotype priors, or observed calls. If an `other`
category is present in the priors, it is retained as a latent pseudo-allele so
that founder and background distributions normalise correctly.

The non-missing call state space is:

```text
S_locus = {partial(a) for a in A_locus}
          union {complete(a,b) for unordered a,b in A_locus}
```

## Authentic Dropout Component

Although genotypes are represented as unordered allele pairs for inheritance,
the dropout model operates on two physical allele copies. Homozygous genotypes
therefore contain two independently droppable copies of the same allele.

Let `d` be the per-copy dropout probability. Each copy is retained with
probability `1 - d` and dropped with probability `d`.

For a homozygous genotype `{a,a}`:

```text
P_raw(complete(a,a) | {a,a}) = (1 - d)^2
P_raw(partial(a)    | {a,a}) = 2 d (1 - d)
```

For a heterozygous genotype `{a,b}`, where `a != b`:

```text
P_raw(complete(a,b) | {a,b}) = (1 - d)^2
P_raw(partial(a)    | {a,b}) = d (1 - d)
P_raw(partial(b)    | {a,b}) = d (1 - d)
```

All other non-missing calls receive probability 0 in the authentic component.
The probability that both allele copies drop out is `d^2`. Because empty calls
are not scored observations in this analysis, authentic probabilities are
conditioned on a usable non-empty call:

```text
Z_auth = 1 - d^2
P_auth(O | G,d) = P_raw(O | G,d) / Z_auth
```

for `O` in the non-missing call state space.

## Background-Error Component

A small model-independent background-error mixture gives finite probability to
non-missing calls that cannot be generated by the authentic genotype. The
background-call distribution is derived from one fixed reference locus-specific
population frequency file shared by all runs. It is held constant across
pedigree structures and founder-sensitivity settings and does not inherit
person-specific or scenario-specific founder restrictions.

Let `q_locus(H)` be the Hardy-Weinberg genotype prior induced by the fixed
baseline allele-frequency table for a locus. The background call distribution is:

```text
B_locus,d(O) = sum_H q_locus(H) P_auth(O | H,d)
```

for `O` in the non-missing call state space.

Let `rho` be the background-error mixture rate. The scored non-missing
observation probability is:

```text
P(O | G,d,rho) = (1 - rho) P_auth(O | G,d)
                 + rho B_locus,d(O)
```

Missing observations remain uninformative:

```text
P(missing | G,d,rho) = 1
```

## JSON Configuration

The supplied all-locus runs use:

```json
{
  "type": "generative_str",
  "dropout": 0.2,
  "background_error": 0.001,
  "background_source": "fixed_reference_frequencies",
  "background_frequency_file": "../../data/background_allele_frequencies.json",
  "missing": "condition_on_call_available"
}
```

The background frequency file is shared by all seven configurations and remains
unchanged when founder priors are varied. Founder frequencies and background
frequencies are separate engine inputs. Sensitivity reruns vary the dropout and background-error settings as documented
in `Results/Primary_All_Locus_Sensitivity/`.

## Validation Coverage

The validation code checks:

- normalisation of authentic non-missing call probabilities;
- homozygous one-allele calls with two independently droppable copies;
- heterozygous complete and partial calls;
- background-call normalisation under locus-specific allele frequencies;
- finite probability for mismatching observations through the background-error
  component;
- uninformative treatment of missing calls.
